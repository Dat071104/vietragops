## B0.1 — Exact metric implementation

Gate 12-V calls `evals.metrics.generation_metrics.token_f1(expected, actual)`.
It uses `rag.retrieval.base.tokenize`, which performs:

1. Unicode NFKC normalization;
2. whitespace collapse and trimming;
3. `casefold()`;
4. Unicode regex `\w+` token extraction;
5. multiset overlap with symmetric precision/recall F1.

Vietnamese diacritics are retained. NFKC composes compatible forms but does not
remove Vietnamese accents. Digit strings are ordinary tokens; no numeric
canonicalization or zero-padding normalization exists.

Removing only that prefix changes mean raw token-F1 on those 10 rows from
`0.193593` to `0.200230`, a mean gain of `+0.006638`. It is a real but small
effect compared with verbosity and retrieval/refusal errors.

## B0.6 — Disagreement and corrected metric proposal

The frozen automated metric marks `7/36 = 19.4%` correct. All seven are
human-correct. It misses 11 human-correct rows below `0.45` and has zero false
positives. Disagreement is therefore `11/36 = 30.6%`.

Before applying a corrected score, the proposed audit metric is:

- NFKC/casefold/whitespace/tokenize as before;
- canonicalize digit runs to integer form (`07 -> 7`);
- strip only the observed generated prefix `Theo ngữ cảnh đã truy xuất,`;
- report symmetric normalized token-F1 **and** expected-token containment
  recall (`overlap / expected-token count`), because extra supported detail
  should not reduce correctness;
- retain hand adjudication as the validation target, since containment alone
  overcredits verbose wrong answers (`dev_q008`, `gold_credit_requirement_023`).

The corrected normalized token-F1 mean is `0.228619`; at the original `.45`
threshold it still marks `7/36`. Containment mean is `0.500659`; a diagnostic
`>=0.60` cut marks `16/36`, but is not accepted as ground truth because it still
misclassifies verbose wrong answers. The validated corrected headline for this
closed artifact is human-adjudicated OpenRouter correctness `18/36 = 50.0%`
(Wilson 95% `0.344741–0.655259`), versus the original automated `7/36 = 19.4%`
(Wilson `0.097530–0.350284`). If partial answers are counted as useful, the
upper useful-answer rate is `20/36 = 55.6%` (Wilson `0.395808–0.704590`).

This is an addendum only; `GATE_12V_RESULT.md` is not rewritten and the golden
dataset is untouched.

## B0.7 — Arithmetic checkpoint

The adopted dense top-10 retrieval ceiling is `88/116 = 75.86%`. With perfect
generation and perfect ranking inside the retrieved set, the `>=0.70` threshold
is reachable in principle because `75.86% > 70%`.

Under Gate 12-V's observed conversion, the estimate is:

`(19.444% / 61.207%) × 75.862% = 24.1%`.

This agrees with Nemotron served-only correctness `6/25 = 24.0%`. Therefore the
frozen `>=0.70` threshold is not reachable under the observed provider-quality
regime, even though it is not mathematically impossible with a generation
system that converts retrieved evidence much better.
